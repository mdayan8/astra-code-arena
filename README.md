# ASTRA Code Arena

The campus coding competition platform of **ASTRA Club, PES Institute of Technology and Management, Shivamogga**.
Build once, then run any number of independent competitions every semester from one installation on the college LAN.

- **Student portal**: one-screen landing with a live leaderboard, sign-in with USN + date of birth, self-service password recovery, dashboard with streaks and badges, a competitive profile (rank, percentile, 12 badges, activity heatmap), competitions, a browser IDE (Monaco) with Run / Submit, live leaderboards, semester leaderboard, practice problems, profile and history.
- **Private Admin Control Centre** on a secret, configurable route: competitions, question bank with versioning, question import from PDF / Word / text / photos (OCR), an AI assistant with a self-checking harness for small local models, test cases written by hand, generated by script in the sandbox or suggested by AI, participants (CSV import), live monitor, fair-play tracking (pastes, tab switches, code replay, similarity check), submissions, leaderboards, semesters, CSV reports, admin users, audit log, system health and backups.
- **Judge**: a separate worker process/container compiles and runs C, C++, Python, Java, JavaScript (plus Go and Rust if installed) against hidden tests. No network, read-only filesystem, a dedicated unprivileged user per job, and CPU/memory/process/output limits.

- **AI Studio** (optional, runs on a ~1 GB local model): question generator and document-to-question converter with a sandbox-checked self-repair harness, plus a **Tools Lab** where organisers describe a tool (hint coach, error explainer, code reviewer…) and switch it on per competition or for practice.
- **Imports almost anything**: PDF, Word, OpenDocument, PowerPoint, RTF, HTML, Markdown, code files, images (OCR), structured JSON / CSV / Excel question sets and ZIPs of them. Question types: standard, fix-the-bug and complete-the-code with starter code.
- **Database page**: health, table browser, CSV export, maintenance, backups with one-click restore.
- **Campus-only by design**: optional `ALLOWED_NETWORKS` lock, a Sophos firewall recipe that blocks internet during rounds, and an in-arena detector that reports any device that can still reach the internet.

Everything runs offline on the LAN. Nothing loads from the internet (the editor is bundled). AI is optional.

## Stack (deliberately small)

| Part | Choice | Why |
|---|---|---|
| Backend | Python 3.12 + FastAPI | One small process. 300 students polling every 15 s is about 40 requests/s; the load test below shows it handles that with room to spare. The heavy work (compiling and running code) is done by native compilers in the judge, not by the web server, so a Rust rewrite would not make judging faster. |
| Database | SQLite (WAL) | Zero setup, one file, easy backups. Upgrade path: PostgreSQL if you ever need thousands of concurrent writers. |
| Frontend | Plain HTML/CSS/JS + Monaco | No build step, no CDN, ~150 KB of app code. |
| Judge | Linux rlimits + per-job uid + Docker (`network_mode: none`, read-only) | No external judge service needed. |

## Quick start (Ubuntu PC, no Docker needed)

1. Download this repo (Code → Download ZIP, extract it) or `git clone` it.
2. In the folder, right-click `start.sh` → **Run as a Program** (or run `bash start.sh` in a terminal).
3. Press **Install** in the setup window and enter your Ubuntu password. A progress bar shows every step. When it finishes you get the admin password, the student link and the control panel.

After that it runs in the background, starts at every boot, and opens from the app menu as **ASTRA Code Arena**. Full guide: [docs/UBUNTU.md](docs/UBUNTU.md) (also inside the app under Guide & help).

The Docker route (`./deploy.sh`) still works for servers that already use Docker.

Full instructions: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) (LAN and Wi-Fi checklist for the IT team included).

## Run locally for development (macOS/Linux)

```bash
pip install -r requirements.txt
python -m app.manage create-admin
python -m app.main        # web on :8000
python -m app.worker      # judge (second terminal)
```

On a laptop the judge runs in *reduced* isolation (limits only); the full sandbox needs Linux as root, which is what Docker gives you.
